# The app pass — plan

*2026-10-31. Decided with the owner on the design page
(https://claude.ai/artifact/4rq6e21KH7EkT5FPFigD9X): D1 Linen + Onyx following
the system, D2 identity card + hold-to-write, D3 Albums · Library · iPod with
a log strip on every screen, D4 Nunito.*

The brief, in the owner's words: "a whole pass on the app — making the user
experience more intuitive, adding the logo to the app title, mono chrome
colorway like we have on the iPod."

The app is `core/cli/internal/app` (Gio v0.8.0, pure-Go Windows build,
`-tags novulkan` on Linux). Everything below is drawn from a code inventory of
that package and from host renders of every canned state
(`core-app --screenshot … --state … --tab …`). The inventory's findings that
drive the pass:

- Update hides behind Details → Check; nothing checks GitHub on its own
  (`startCheck` is only called from the Details button, ui.go:597).
- Flash and Update end in `flashFile` and return straight after `be.Flash`;
  Install ends with `be.Refresh` (actions.go:308). The detect poll keys on
  `path|serial` (detect.go:138), which a flash never changes. So the window
  kept saying v0.2.0 after the v0.2.1 update.
- The music folder can be set in four places; Eject (`ejectBtn`, drawn twice
  per frame: ui.go:837 + details_tab.go:189), Update and Install are
  duplicated; `syncBtn` is declared and never drawn.
- Jargon on the front: OSOS, CORECFG.DAT, CORELOG.BIN, CORELIB.IDX,
  `\\.\PhysicalDrive2`, "sector 2048 B", "Dry run", "Sync + prune", the path
  to core.exe in the tab row, raw art-match scores.
- The log and the only Cancel live on the Details tab; Looking and
  NotInstalled have no log; Cancel is disabled almost always.
- Stale messages: "press Refresh" (ui.go:703, actions.go:72, actions.go:344,
  demo.go:250), "type one in the Music card" (actions.go:69), "press Flash
  file…" (actions.go:187).
- Accent (terracotta) is used for the primary button, progress, footer link,
  warnings, the checkbox tick, the NEW badge and every "Take" button.
- The window title is "Core" (run.go:38); no icon or logo anywhere.

## Design rules for the pass

1. **Monochrome, like the iPod.** Ink on surface. The primary button is the
   iPod's selected row: ink fill, surface text, radius 5. Secondary buttons:
   surface, 1 px border, ink text. Disabled: `PillOff` fill, `SelSub` text.
   Progress bar, badges, ticks, links, focus rings: ink. **Terracotta is for
   warnings only** (untested hardware, missing administrator rights, a job
   that failed) — the same single job it has on the device.
2. **Two palettes, the device's.** Port `PAL_LINEN` and `PAL_ONYX` from
   `core/ui/palette.c` token for token (hex comments there are the source;
   where only RGB565 is given, expand it). Onyx when the system is dark,
   Linen otherwise; a toggle in the "···" menu (System / Linen / Onyx)
   persisted in `config.json` as `"theme"`. "System" on Windows reads
   `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme`
   (pure Go, `golang.org/x/sys/windows/registry`); elsewhere System = Linen
   until there is a signal to read.
3. **The mark.** The boot screen's ring and dot: on a 40-unit box, ring
   r = 17.5 stroke 2.2, dot r = 6, hole r = 2, all ink (the hole is surface).
   Drawn with `clip.Ellipse`/`clip.Stroke` so it is crisp at any DPI. It is
   the window/taskbar icon too: PNGs at 16/24/32/48/64/128/256 generated by a
   script under `tools/` from the same geometry, declared in
   `cmd/core-app/winres/winres.json` as `RT_GROUP_ICON` **`"#1"`** (Gio's
   Windows backend loads icon resource id 1, os_windows.go:72), then
   `go generate` regenerates the `.syso` files.
4. **Nunito.** Embed Regular, SemiBold, Bold from `tools/fonts-src` (OFL,
   ship `OFL.txt` beside them) with `opentype.Parse` into the shaper
   collection; Go Mono stays for the log and dialog plans. Type scale: 16
   brand word (ExtraBold if cheap, else Bold), 14 device name (Bold), 13 body,
   12.5 buttons (Bold), 11.5 sub lines, 11 tile titles. Nothing below 10.
5. **Words.** Verb-first buttons that say what will happen: "Sync 7 albums",
   "Update to v0.2.2", "Install Core", "Delete 3 albums and sync". Renames:
   Dry run → Preview sync · Sync + prune → Sync and remove · Flash file… →
   Choose an image… · Scan again → Rescan · Take → Use this cover · Details
   → iPod. No file names, disk paths or register-level facts outside the
   Advanced disclosure and the log.
6. **One entry point per thing.** Music folder: the Library tab (field +
   Browse). The footer shows it and clicking it switches to Library. The
   empty grid's button opens the same picker. Eject, Update, Install: the
   header only.
7. **Every screen has the log.** A one-line strip at the bottom (last log
   line, mono) that opens into a drawer (the existing log pane) on click, in
   every phase. Copy lives in the drawer.

├ progress (4 dp, ink) ────────────────────────────────────────────────────┤

├ body ────────────────────────────────────────────────────────────────────┤
│                                                                          │

│ Music folder  C:\…\Music\MC        19:41:02  scanned 101 albums, 928 tracks ▴ │

- **Top bar.** Brand lockup (mark 22 dp + "Core") · device block (name
  Bold; model Muted; one status line: firmware · update state · free space)
  · actions: primary (verb-first) · Eject (when a volume is mounted) ·
  "···". While a cancellable job runs, a **Cancel** replaces the primary.
  Looking: device block says "No iPod yet / looking every two seconds".
- **"···" menu** (our own popup, same modal machinery): Back up the firmware
  · Flash an image file… · Read the iPod again · Check for updates · Copy
  the log · Open the music folder · Theme ▸ System / Linen / Onyx · About
  (version, commit, CLI path).
- **Tabs.** Albums · Library *n* · iPod. Hidden in Looking/NotInstalled as
  today. The right-hand note loses the CLI path (iPod tab shows "checked for
  updates just now / never").
- **Albums.** As today, in the new tokens: tiles, NEW badge = ink fill,
  CHANGED = ink outline; already-synced tiles dimmed; tile fallback colours
  come from the palette's muted family rather than hard-coded RGB.
- **Library.** As today with the renames; the per-album art rows lose the
  raw score/provider (log keeps them); "Use this cover" / "Skip".
- **iPod tab.** Rows in one plate: Name (Rename) · Firmware (Update when
  available; "up to date" otherwise; release date + first changelog line as
  the sub) · Storage (free of total, read from the volume; songs/albums/
  genres sub) · Hardware (model, tested/UNTESTED, serial) · Backups (Apple
  backup date; count of partition backups; Show folder · Back up now).
  Below: **Advanced** disclosure holding what the old cards showed: disk
  path, sector size, OSOS entry/length/checksum, index/config/log files,
  the image path field + "Choose an image…" + "Flash this image".
- **Log strip + drawer.** Strip: last line, mono 10.5, chevron. Drawer:
  the existing pane at ~40% height, Copy button, closes on the chevron.
- **Looking.** Centred: mark 48 dp, "Plug in your iPod", one sentence, two
  steps with key caps. NotInstalled: mark, "Core is not installed on this
  iPod", one paragraph (Apple's firmware is saved first; Core is written;
  your music is untouched), [Install Core] [Install from a file…] — the
  second a picker that fills a path and then needs a click, like the
  Advanced flash (today it installs the moment a file is picked).

## Dialogs

- **Write (Flash / Update / Install).** Title says the verb and version.
  Identity card: name · model · serial · "Disk N of M on this PC · size" ·
  what is written (bytes; "the partition is backed up first and read back
  after"; "nothing on the music volume changes"). Recovery sentence. Buttons:
  Cancel · **Hold to write…** (press-and-hold 2 s with a fill that grows
  across the button; releasing early resets). The flasher's typed-path
  prompt is answered by the app with the path it already knows **after** the
  hold completes, and only when `Device.Tested`; for untested hardware the
  dialog keeps the typed-path field as today. The parse of the flasher
  prompt (`devicePathFromPrompt`) stays as the guard that the path the app
  will type is the one the flasher asked for.
- **Sync and remove.** Lists the albums that would be deleted (name, size)
  and the button reads "Delete N albums and sync". No typed word.
- **Fix the library.** As today.

## After-job behaviour

- Flash, Update and Install all end with `be.Refresh` (one shared tail).
- `startCheck` runs once at launch after the first successful Refresh (and
  from the menu); result cached per launch; errors go to the log only.
- Sync ends with a Refresh of the library counts.
- Eject: the device block says "Ejected — safe to unplug" until the poll
  loses it.

## Slices

Each slice is one PR. It builds (`go vet ./...`, `go test ./...` for
`internal/app` under `(ulimit -v 6000000; timeout 240 …)`), cross-builds
for Windows, and ships re-rendered `--screenshot` PNGs of every state ×
both themes into the PR description for review. Review is visual first.

## Not in this pass

Playlists tab (phase 3), macOS/Linux dark-mode detection, moving the CLI's
own output to plain words, anything on the firmware side.

## Facts the implementer should not re-derive

- Host render: `go build -tags novulkan -o /tmp/core-app-linux ./cmd/core-app`
  then `core-app-linux --screenshot out.png --state demo|library|empty|looking|notinstalled --tab albums|library|details --size 900x600 --no-detect`,
  always under `(ulimit -v 6000000; timeout 240 …)` — an earlier layout bug
  allocated 40 GB per frame and took the machine down.
- Windows build: CI's `-ldflags` stamp (release.yml / scripts/build-all.sh)
  plus `-H windowsgui`; staged copies live in `C:\Users\brandon-home\ipod-bringup\`.
- `config.json` is `%AppData%\core\config.json` (`internal/app/config.go`);
  today it holds `source`, `backup_dir`, `names`.
- Gio has no menu widget and no OS-theme signal; both are ours to build.
- The write prompt the flasher emits is
  `This will write to \\.\PhysicalDriveN. Type the device path exactly to continue: `
  (flasher.go:690); `devicePathFromPrompt` parses it.
